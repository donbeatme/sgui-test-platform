## 三条失败的具体原因

### 436：人数要求缺乏可核查依据，前两轮另有生成错误

前置条件和操作写了“1 成人 0 儿童 0 婴儿”，但逐步预期只写儿童、婴儿未勾选。最终脚本仅证明两个勾选项未选，无法证明成人确切数量为 1，覆盖复核因此拒绝交付。前两轮还出现未设置出发城市便先断言上海、依赖城市面板已展开等错误，不能把所有问题都归因于用例材料。

建议在生成前识别这类“明确人数 / 界面只展示乘客类型”差异，要求确定可观察的验收条件。本轮没有擅自改用例，也没有删除人数要求以换取通过。

### 443：前置条件未建立，模型对当前页面作出矛盾判断

首轮代码没有实际设置“不限舱等”，后续核对保持条件时停止。末轮更在第 0 批就报告“只有经济/超经舱等选项，不存在不限舱等”，但同一轮保存的 `live_page.dom` 中，`visible=true` 的 `div.form-select-v3` 明确显示“不限舱等”，单选组显示往返选中。

这证明模型停止理由与当前现场存在矛盾；可能受历史失败内容影响，但具体干扰机制尚未证实。不能据此认定携程不存在该选项或业务有缺陷。需要让当前 DOM 的事实优先于历史结论，并让可调整的初始状态先进入准备操作。

### 444：先通过后失败，自动修复又丢失原有前置

第一轮漏掉“先清空出发地并点击搜索触发校验”。第二轮补上后，run 80 通过，但 run 81 的搜索按钮被 `city-picker-tabs` 拦截，15 秒点击超时。第三轮又漏掉先触发空城市校验的前置，覆盖复核不通过。

需要显式关闭遮挡面板并确认状态，且修复时保留已实现的前置条件，避免在解决一个错误时退回到已经发现的遗漏。中间一次通过不算最终交付成功。

## 人工核查与适用边界

逐条对照了最终代码、冻结步骤、平台复核结果；另查看 431 的日期高亮、410 的同城校验、444 的遮挡失败截图。

- 431：日期高亮、星期、城市和儿童婴儿状态有运行证据；但舱等只检查当前值，没有落实“回填不符时重选”的全部前置处理。
- 433：日期恢复和星期列对齐有断言；“面板覆盖表单上方区域”没有几何关系验证，不能由面板可见直接推导该布局符合。
- 434：无错误提示只检查 `aria-invalid`，可能漏掉网站使用 CSS 或自定义文案的错误提示；不能声称已验证所有错误提示都不存在。
- 431、433、435、410：日期或星期写在代码中，跨日、跨月或修改测试数据后不能保证继续有效；仅修改日期参数可能不足以更新整份脚本。
- 多份脚本仍使用选项顺序、`.first` 和宽泛的选中样式候选，当前运行通过不能保证页面结构调整后仍然稳定。
- 本轮没有登录、下单、付款；样本集中在查询表单及输入校验，不证明结果列表、登录态或多站点能力。
- 7 个可用版本已通过产品下载接口导出并检查 Python 语法；运行成绩来自平台执行器，没有另行宣称导出的文件已经在外部独立环境执行过。

## 下一步建议

1. 把前置条件编译成明确的准备阶段，并在复跑前确认：原步骤不能依赖人工已经完成上一条用例。
2. 增加“模型判断与当前页面事实冲突”的检查：如果当前 DOM 有目标值，不允许仅凭旧错误直接判不存在。
3. 对浮层统一执行关闭、确认和点击，自动修复保留已通过的前置与业务断言，避免整轮重学造成退化。
4. 将日期和星期统一参数化，优先稳定语义定位；补强错误提示、选中状态与布局相关断言。
5. 对已完成步骤和模型复核结果做合理复用，避免局部修复反复从入口开始；随后用同一固定样本重新评测，不追加尝试来改写本轮成绩。

## 评测口径

- 通过平台正常“生成脚本”接口调用当前 `guided-v1`，模型为配置 6 的 `deepseek-flash`。
- 固定 10 条现有用例，保留原始步骤、预期和 revision。443、444 是此前已经用户批准的修订版，本轮没有再次修改。
- 串行，可见 Chromium，独立浏览器上下文，不继承个人浏览器登录状态；单次独立复跑超时 180 秒。
- 产品默认最多 3 轮生成（初始 + 2 轮自动修复）；不人工修改脚本、不重启失败任务追加机会，不在评测中修改产品代码。
- 首轮可用率：第 1 轮完成生成、覆盖复核和两次独立复跑的用例数 / 10。它不是“单次 LLM 调用”成功率，单轮内部本来包含多次模型交互和操作恢复。
- 最终交付可用率：默认自动修复预算内，状态 ready、usable=true、最终版本两次独立复跑通过的用例数 / 10。
- 独立复跑通过率单独统计，不能把“只对交付成功脚本复跑”的结果当成全部样本生成成功率。
- 若复用了同用例当日已验证的完整代码，单独标记，不冒充新模型生成。历史定位线索属于当前产品默认机制，允许使用并披露。
- 模型超时、生成失败、业务预期不符、环境阻塞全部计入这 10 条的非成功项，另分原因统计。不以“网页打开了”替代业务断言。
- 样本集中于携程机票查询表单和输入校验，不代表航班结果、登录、下单支付或其他网站的准确率。
