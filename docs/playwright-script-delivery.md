# Playwright 脚本生成与交付

## 用户操作

1. 在项目配置中设置被测网站地址，并启用可用的 LLM 模型。
2. 在用例管理选择已有用例，点击“生成脚本”，使用默认的生成并验证方式。
3. 等待显示“复跑通过”，进入“Playwright 脚本 → 代码与记录”。
4. 点击“运行”在平台复用；或者点击“下载运行包 ZIP”，在其他电脑独立运行。

生成过程中可以关闭配置窗口。失败时页面保留原因和版本，不需要用户逐条编辑中间草稿。

## 当前实现

新的生成任务采用 `guided-v3`：

- 执行器打开真实页面，把 DOM、可访问性信息和当前字段状态交给 LLM。
- LLM 分批完成原用例，支持局部变量、读取页面状态、条件分支和有限循环。
- 先保存成功执行的代码和现场，随后基于这些证据整理为连贯脚本，去掉探索与修复中重复的选择、打开和核对动作；原始操作记录仍保留。
- 出错时依据现场和未完成代码继续修复；复跑失败时在生成阶段修订，最多初始生成加两轮修订。
- 生成完成后打开新的浏览器上下文，执行同一份脚本一次。完整执行且无错误才交付。

基础标准不要求额外的覆盖率审核、每步断言配额或连续两次通过。默认优先完成原用例操作和关键、可观察结果，不强制逐项转换全部预期为断言；颜色、几何位置、日历高亮等不作为基础交付门槛。每个新版本会保留这一验收范围说明，不能将“复跑通过”理解为全部业务需求已验证。
页面状态不同时可以用条件分支建立初始状态；真实断言失败、登录阻断和网站不可用不会自动标记为通过。

隐藏弹层副本不再直接触发“多个面板”错误：公共选择操作从当前可见弹层内定位选项；多个可见候选仍需要明确定位。

此方案参考 [Playwright Test Agents](https://playwright.dev/docs/test-agents) 的真实页面探索、生成和执行修复流程。
未引入 Browserbase 或其他新的云服务依赖。平台使用现有配置的模型，普通脚本复跑不调用 LLM。

## ZIP 文件内容

| 文件 | 用途 |
| --- | --- |
| `case.py` | 独立 Python Playwright 脚本，含必要的通用操作助手 |
| `requirements.txt` | 锁定 Playwright 版本 |
| `case.json` | 来源用例快照 |
| `README.md` | 安装、参数配置、运行和结果查看方法 |

解压后安装依赖并运行：

```shell
python -m pip install -r requirements.txt
python -m playwright install chromium
python case.py
```

可选参数：

```shell
python case.py --headless --timeout 240 --output results/run-2
python case.py --base-url https://your-site.example --params '{"origin":"Paris"}'
```

运行结果保存在指定输出目录，包含 `result.json`、逐步截图和 `trace.zip`。
使用 `python -m playwright show-trace playwright-results/trace.zip` 查看操作轨迹。
返回码为 0 表示本次运行成功，失败或停止返回非零。相对日期在每次运行时重新计算。

运行包不需要平台账号、后端、数据库或模型 API Key；需要 Python、匹配的 Playwright/Chromium 及目标网站访问条件。
若用例需要登录，应按目标测试环境提供认证前置条件；包不会复制个人浏览器登录数据。

## 部署兼容性

- 新生成任务需要上报 `runtime_version >= 11` 的执行器。
- 后端、执行器和前端需一起更新；后端与执行器的通用操作助手保持一致。
- 已保存的旧脚本、原用例及历史执行记录保留。
- 同一版本通过一次复跑证明当次可执行，不代表所有网站、日期或业务数据下均能通过。

## 开发验证

后端测试覆盖格式检查、变量作用域、条件分支、受限运行时访问、构建状态和独立下载包。
执行器测试使用真实 Chromium 验证变量跨批次保留、隐藏弹层副本、歧义定位和失败结果保留。
另通过产品 API 对真实网站的既有用例生成脚本，并下载 ZIP 在独立进程复跑，分别记录生成结果和导出复跑结果。

新生成任务默认缩短页面视觉动画，生成、复跑和下载包使用相同策略；不强制点击隐藏或禁用控件。下载脚本可用 `--native-motion` 恢复网站原始动画时序，此模式需另行验证。
