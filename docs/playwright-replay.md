# Playwright 脚本保存与复跑

## 使用

### 直接从测试用例生成

1. 在项目管理的系统凭据中填写被测网站地址，并启用一个可用 LLM；用例应有完整操作步骤和预期。启动更新后的执行器（运行版本 9 或更高）。
2. 在用例管理点击 **生成脚本 → 开始生成**。默认执行完整生成与验证流程，页面仅展示“生成中”“可用”或失败原因，可以关闭窗口继续工作。
3. 后台冻结用例与入口，创建独立浏览器会话。模型根据当前 DOM/ARIA 决定一小批操作或断言；打开新面板后重新观察，再处理其中控件。执行器逐句确认实际结果，只有成功执行的语句进入代码记录。
4. 按原始步骤顺序组装这些语句，检查语法、运行接口、参数与步骤结构。新任务不再单独调用 AI 做准备规划与覆盖复核，也不强制每步都有断言；已有断言仍会真实执行。模型不会再依据日志重写整份已执行代码。若有同一版用例、同一入口、当天验证通过的脚本，可以复用代码，但仍须重新验证。
5. 最终版本在一个全新的独立浏览器环境中完整复跑一次，无执行错误即显示 **复跑通过** 并开放运行、下载。发现问题会在生成阶段自动重新观察和修复，最多初次加两轮修复；不要求用户逐个处理草稿。原用例的步骤、预期和失败记录均保留，不通过删除失败断言来放行。此标准验证脚本能重跑，不代表业务覆盖已经完备；历史任务仍保留原有验收标准。
6. 在 **测试管理 → Playwright 脚本** 点击 **运行** 或 **代码与记录 → 下载 .py**。普通运行直接执行保存的代码，不调用 LLM。生成验证是真实执行，报告进入执行历史；只有采集过程结束不代表用例通过。
7. 失败时查看原因并点击 **重新生成**。技术详情和手动编辑保留在高级视图。用例修改后，应从用例管理新建生成任务，以冻结新的步骤和预期。

高级设置中的“仅生成草稿”及从 LLM 执行记录整理保留旧工作方式：只做代码与覆盖检查，不会自动实测，需单独验证，不能当作已交付脚本。

相对日期（例如“执行当天至少七天后”）可通过 `{{date:7:iso}}` 等参数模板在每次执行时解析，并同步星期；脚本不会擅自修改用例明确指定的固定日期。参数格式及当前生成策略见 [生成流程说明](playwright-generation-v2.md)。

生成器可参考同项目、同入口实际运行通过的历史脚本定位器；只复用控件定位依据，不复制其他用例的业务目标。重新整理会携带失败步骤、URL、标题和可获取的页面结构快照，有助于修正旧代码；快照是历史现场，并不保证网页一直不变。

### 从 LLM 实际执行记录保存

1. 在项目管理配置被测网站地址。在用例管理点击“执行”，勾选“保存本次执行的 Playwright 脚本”（默认不勾选）。
2. LLM 按现有流程操作网页。平台记录本次浏览器工具参数、输出及来源用例快照，不修改原预期结果。
3. 原执行结束并写入报告后，后台用模型将真实记录整理为 Playwright Python 代码。此阶段不重复操作网站，不增加执行次数；整理失败不影响原执行结论。
4. 打开“测试管理 → Playwright 脚本”。执行记录生成的代码先显示“待验证”，检查通过后可“验证运行”；实际通过显示“可用”。存在问题时在“代码与记录 → 技术详情”查看阻塞原因、版本和提示。
5. 查看代码和冻结预期，可修改代码与默认参数并保存新版本。旧版本保留，编辑可以撤销。下载得到可独立运行的 `.py`，文件内含依赖和命令说明。
6. 点击“运行”，选择在线执行器、运行参数、可见/无头模式和总超时。默认沿用唯一的项目地址；提供 `base_url` 可覆盖本次地址。日期、搜索词等可在 JSON 参数中修改。
7. 在脚本的“运行记录”或“执行历史”查看报告、每步截图、失败原因。执行历史标注“Playwright 脚本”；首页统计沿用统一执行记录。可停止当前执行，停止后的迟到结果不会覆盖取消状态。

## 执行器

后端更新后执行 `python manage.py migrate` 并重启 Web/Celery。按主 README 安装并启动更新后的 Python 源码执行器 `Actuator/main.py`。执行器每次任务创建独立浏览器环境，不自动同步个人浏览器登录状态。

脚本队列接口要求执行器使用平台 staff 管理账号登录；普通项目成员仍按项目成员关系与用例权限访问脚本。旧版执行器 exe 不包含新队列，需要更新源码执行器，不能仅替换前端。

执行器使用已安装的 Playwright Chromium。需要可见浏览器时执行器应运行在有桌面的机器上；容器执行器选择无头模式。无需为脚本运行配置模型或 MCP；从用例生成、从执行记录整理或重新生成代码时需要模型可用。

密码等参数不要写入代码或默认参数。执行器启动环境可设置 `SGUI_PARAM_password` 等变量；代码通过 `params["password"]` 引用。不要把执行器环境中的凭据用于不可信项目。

## 代码格式与边界

脚本格式为 `async def run(page, params, record)`。每个原用例步骤使用 `async with record.step(编号)`，其内包含 Playwright 原生操作与 `await expect(...)` 断言。执行器负责独立浏览器、超时、逐步截图、回写结果与取消。

首版支持单页面导航、点击、输入、按键、选择、勾选、悬停、等待以及常见元素/URL/文本断言；定位支持 role、label、placeholder、text、test-id 和 CSS。复杂 `evaluate`、多标签页、任意 Python/系统调用不自动复跑，整理时标记为需修订。不能只将一次性浏览器 ref 复制为长期定位器。

支持在 f-string 中插入 `params["参数名"]` / `params.get("参数名")` 构造日期等定位器，不支持其他插值表达式或格式指令。支持 `to_have_css`，可将只读 DOM 观察转换成透明度等原生断言。

模型混用 JavaScript 的 `.first()` / `.last()` 时，保存前会自动转换为 Python 的 `.first` / `.last` 并留下提示。页面错误文案不存在可用 `not_to_contain_text(..., use_inner_text=True)` 验证。

仅生成草稿和执行记录整理区分阻塞问题 `blockers` 和运行提示 `warnings`，出现代码格式问题或明确的验证遗漏时最多自动修订一次，仍有问题则保存草稿并显示具体原因。对模型误写入提示的明确验证遗漏，接口和执行器领取入口都会重新拦截。此检查不能证明全部业务预期已被覆盖。旧版本不自动清除问题；可点击“重新整理为新版本”使用新规则重新生成。运行提示也会显示在启动窗口，不要求逐条确认。固定日期不会自动滚动，运行前请核对日期及相关星期参数。

模型返回的 JSON 引号或换行格式不合法时，一次生成任务最多进行一次格式修复，随后仍完整执行代码与业务覆盖校验。修复失败保留已有版本并给出明确提示；不会无限重试或将错误输出直接当作可运行代码。

高级视图的“重新整理为新版本”会参考上一版代码、参数与该版本最近的失败记录，保留已修订的可靠定位和完整断言。生成后仍须复跑验证，不会自动反复操作目标网站。复跑记录保留在原版本下。

格式检查不能证明业务断言正确，首次使用应对照冻结的原用例核查。页面布局、动态日期、账号状态或风控变化仍可能导致复跑失败。保存脚本不会承诺对第三方页面长期稳定。

### 动态浮层的稳定操作

生成规则优先使用 `record.choose_option` 处理城市、日期和非原生下拉选项：先确认对应浮层已打开且动画稳定，再在该浮层内选择唯一候选，最后核对输入框完整值。面板已打开时不会重复点击入口；透明或隐藏的面板会重新打开。定位器和选值必须来自真实执行记录，不能用任意 `first` 绕过同名元素。

`record.ensure_open(trigger=..., panel=...)` 可单独准备面板，`record.expect_closed(panel=...)` 可检查面板收起，兼容移除、隐藏和透明状态。公共操作的定位器都以 `page` 开始；原业务预期指导生成，基础复跑模式不强制每步包含 `expect` 断言。

仅当选择操作超时且面板确实已关闭时，`choose_option` 才会重新打开一次。选中值错误或业务断言失败不会重试；提交、删除、支付等操作不能使用选项恢复。报告保留首次超时阶段、恢复次数以及恢复前截图（每步最多 4 张），并继续保存步骤结束截图。恢复前截图不能代替通过时的结果证据。

升级时同步更新后端和执行器。使用公共操作的新脚本需要执行器声明运行版本 1，旧执行器会收到明确提示。下载的独立 Python 文件也包含相同公共操作，无需额外下载辅助文件。维护时 `Django/playwright_scripts/runtime_actions.py` 与 `Actuator/replay_actions.py` 必须同步，执行器测试会校验两份内容一致。

### 根据实际条件继续、阻塞或标记不适用

生成器结合用例名称、前置条件、操作与预期判断适用条件，不会因为一句“不判通过”就无条件停止。`record.guard_state(states={...}, outcomes={...})` 按本用例的页面定位证据重新观察状态，状态名称由用例定义，不内置网站域名、选择器或登录文案。

- `continue`：当前状态适用，继续完成后续业务操作与原始断言。
- `blocked`：实际阻断或无法可靠判断，保存现场并停止。
- `skip`：已观察到明确状态，证明本条条件场景未触发或不适用。结果单独显示，不计为通过、失败或阻塞；后续步骤记为未执行。

同一正常表单可在普通业务用例中映射为 `continue`，在专门的异常处理场景中映射为 `skip`。缺少定位器、没有观察证据或断言失败不能作为跳过的理由。正常背景和阻断弹层同时出现时阻断优先；其他冲突也会阻塞。导航栏的登录入口不能证明必须登录。

`observe_state` 仅观察状态；`stop` 保留给明确无条件停止的需求。新状态分支需运行版本 3 的执行器，下载代码包含相同实现。报告中的不适用结果必须包含本轮状态依据和截图，否则后端按阻塞处理。普通业务断言失败仍然为失败。旧版本和旧执行结果保留；点击“重新整理为新版本”采用新规则。

`record.step` 内的导航失败、网络错误和超时由运行器统一记录原始错误、页面地址和截图，并标记阻塞；生成和覆盖评审会计入这些运行器能力，不要求脚本重复编写异常捕获。特定错误文案、状态或恢复操作等业务预期仍须单独实现，不能用通用异常记录代替。

URL 断言 `to_have_url` 采用完整地址比较，不接受 `**example.com**` 之类通配符字符串；保存版本和启动运行都会检查参数，运行时覆盖参数也不能绕过检查。

脚本、不可变版本与运行元数据在 PostgreSQL 中保存；截图继续使用平台 media 存储（本地 Compose 对应项目 `data`）。删除脚本会从列表移除，已有历史报告与运行版本继续保留。逐步生成的操作记录来自本轮执行器的真实确认；不会补造历史 LLM 执行记录。

## 验证

后端：`python manage.py test playwright_scripts testcases.test_execution_tracking --noinput`

执行器：安装浏览器后，在 `Actuator` 中运行 `python -m unittest test_script_runner test_script_guided -v`。该测试只操作临时本地网页，覆盖真实浏览器通过、断言失败、超时、截图、同名候选范围、透明/已展开浮层、关闭后恢复与恢复现场保留。
