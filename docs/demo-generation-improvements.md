# 业务流程生成与演示准备改动（2026-10-12）

## 生成

工作台新增任务级 `generation_profile`，在提交时冻结，不改历史任务：

- `scenario`：场景演示，最多两条完整流程；一个业务模块、一个完整材料批次。全部相关原文、共享规则与最多 6 张原图共同参与生成和评审；超预算时提示精简材料，不将图文拆开。适合事先收敛到 1–2 个业务场景。
- `workflow`：前端默认；最多 4 个业务目标模块，每批最多 8 条，强调独立完整流程、材料支持的边界及恢复。
- `quick`：最多 2 个业务目标模块，每批最多 3 条代表性流程；材料多时仍会分批，不承诺总条数或时间。
- `detailed`：保留原功能模块模式；旧任务及未传该字段的调用保持原行为。

材料仍须完整归类。新增生成批次可看到前面已生成的场景标题，避免同义重复；不自动删除语义相似的测试。原文、截图、依据校验及人工确认不被跳过。

图片控件与视觉事实已经在证据列表中存在时，不再向生成/评审模型重复附送同一份完整解析 JSON。排除项、未知项和证据 ID 保留，原始内容仍存断点，原图仍附送。分批预算按实际材料结构估算，不再只统计原文长度。

后续双场景调整进一步移除证据项中与所属材料重复的文件名、页码等元数据，完整事实、摘录、编号和原始断点不变；来源详情仍由服务端按编号解析。已结构化的图片事实直接用于目录，不再额外调用模型重复摘要；场景模式直接使用共享原文。已验证模块规划在续跑时复用。

控件列表直接显示“AI 原始识别 / 人工修订”，详细处继续保留模型原值及修订记录。提示词加强范围选择、可见状态与行为推测区分、标注框不确定时留空；这些调整不代表识别准确率已被量化或所有标注框都正确。

图像解析参考明确的业务范围，少列无关广告和导航。流程模式额外检查状态准备、操作衔接、动态数据写死和异常恢复。

结果页显示已完成模型请求数及累计请求时间，不将人工审核、排队时间混入模型耗时；不宣称固定提速比例。

## 执行

- 冻结用例已包含项目入口和完整步骤时，提示模型直接使用，减少重复查询。
- 城市/日期弹层遮挡时先取最新快照、正常关闭/选择，再重试；不使用强制点击或删除遮罩。
- 三次工具失败仍有上限，保护停止时输出结构化 blocked 结果及最后错误，缺失步骤保留未执行。
- 执行日志保存工具错误摘要，避免只显示工具名；正常网页全文和密钥不复制进诊断摘要。
- 模型 HTTP 400/401/402/403/404/422 不再反复重试。429/连接异常仍使用原有限重试策略。
- 不放宽原步骤预期一致性、本轮截图归属和通过判定。
- 长流程执行预算从固定 80 次调整为基于冻结步骤数 `min(200, max(80, 20 + 10 × 步数))`；11 步为 130 次、15 步为 170 次。仍保留连续同工具失败 3 次停止、总调用硬上限和执行超时。减少重复整页读取，局部观察已足够时不重复检查。预算增大并不等于执行速度提高。
- 执行历史“总数”改为“本次用例数”。
