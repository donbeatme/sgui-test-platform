# 独立感知与图片控件检查

本次在 2026-10-28 交付源码上补充 `perception/`，并将图片核对面板作为独立页签，位于“需求与图片”和“用例结果”之间。
不增加数据库迁移；识别进度与核对结果使用原任务的 JSON 字段，原始感知 JSON 单独存放在平台媒体目录。

## 使用流程

1. 在“需求与图片”准备原有需求材料，选择图片控件识别方式。
2. 默认“独立感知模块”逐张调用本机 OCR + YOLO；也可选择原有视觉模型解析方式。
3. 含图片的任务先进入“图片控件检查”，对照原图查看分区、位置、文字、图标与控件类型。
4. 可以补充遗漏、排除误识别、调整文字和类型、修改区域或重新框选。切换到“用例结果”不会丢弃未保存的控件修改。
5. 逐张勾选已核对，再点击“按核对结果继续生成”，回到原有用例生成流程。
6. 用例草稿编辑、依据确认、覆盖检查、导出和入库继续在原“用例结果”中使用。

仅文字或需求文档、且不分析内嵌图片的任务直接走原有生成路径。
独立感知识别不要求配置平台视觉模型；后续生成仍使用原有文字模型配置。
旧任务未指定识别方式时保留原有视觉解析行为。
若某张识别失败，从断点继续时只处理未完成的图片，不重复已完成图片。

## 接入位置

- `perception/`：独立环境、模型下载校验、识别 CLI 和 HTTP 服务。
- `Django/guicase_workbench/perception_client.py`：读取上传图片并调用感知服务，原始结果单独保存。
- `controls.py`：将感知的像素坐标转换为工作台已有的归一化坐标，保留分区和来源；旧视觉解析提示词保持原样。
- `pipeline.py`：仅在选择独立感知时增加识别分支，完成后复用原有控件核对、生成和评审阶段。
- `GuiCaseWorkbenchView.vue`：新增独立页签及阶段跳转。
- `ImageControlPanel.vue`：沿用上一版分区控件检查界面，支持原图裁剪、人工补充与修改。

原有核对上限为每图 60 个控件，感知识别多于该数量时在 unknowns 中提示，完整原始识别结果保存在媒体文件中。
控件坐标只作为截图证据，不作为 Playwright 的网页定位器。
此目录是源码集成结果；不会自动复制旧数据库、旧账号或启动替换正在运行的服务。

## 安装与验证

感知服务的环境、模型和连接配置见 [perception/README.md](../perception/README.md)。
前端按原 `Vue/package-lock.json` 执行 `npm ci`、`npm run build`。
工作台后端回归测试使用 PostgreSQL 环境执行：

```bash
python manage.py test guicase_workbench --noinput
```

新增 `test_perception.py` 覆盖识别暂停、人工修改后继续生成、失败断点恢复、无视觉模型时的感知识别和文本任务兼容性。
前端浏览器回归测试：

```bash
cd Vue
npx playwright install chromium
node tests/perceptionWorkbench.test.cjs
```

该测试使用合成图片与模拟 API，不使用业务账号或模型额度，检查页签顺序、未保存修改保留和继续生成时的跳转。
可设置 `SGUI_TEST_CHROME` 使用已有 Chrome，`SGUI_TEST_SCREENSHOT` 保存验证截图。
