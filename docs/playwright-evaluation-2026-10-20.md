# Playwright 实测生成验收记录（2026-10-20）

**当前结论：用户批准的修订样本达到 7/8（87.5%），原始样本仍为 6/8（75%）。** 修订样本由原用例 431–436，加上经批准另建的 443、444 组成；没有删除失败项或扩大分母。通过的 7 条最终版本各做两次独立复跑，**14 次均通过**。这是经过修复后的样本成绩，不是首次生成成功率，也不能保证其他网站达到同样比例。

DeepSeek 额度恢复后，两条修订版继续通过平台执行实测生成。444 的 build 47 在第二轮试跑通过，随后两次独立复跑通过；443 的 build 46 三轮用尽后仍失败。原用例、402 错误、旧版本与每次失败报告均保留。

## 验收范围与口径

- 主样本为测试前冻结的携程用例 431–438。冻结文件包含名称、前置、全部步骤、预期和 revision。
- 运行使用可见 Chromium、独立上下文，不继承个人浏览器登录状态；并发为 1。
- 样本覆盖行程准备、城市互换、日期调整、行程与乘客舱等核对、组合操作、清空与校验恢复。它们集中于机票查询表单，不能代表所有网站、登录、支付、多标签页或其他复杂业务。
- 只有完整步骤及业务断言真实通过，才计为通过。草稿、阻塞、跳过、模型服务错误和诊断采集均不计入成功。
- 生成期间进行了代码迭代和多轮试验。最终结果是经过修复后的验证成绩，不是从零首次生成的统计。
- 已验证代码可在同一冻结用例、同一入口、同一天的重建中复用，但新版本仍须重新试跑；不能把这种复用算成新的模型首次生成成功。
- 脚本的相对日期在生成时转成默认参数。跨日复跑前需更新日期及星期，或重新实测生成。

## 获批修订版与剩余问题

用户确认“按实际界面修订，保留原版本”。据此另建：

| 原用例 → 修订版 | 脚本 | 修订范围 | 最新情况 |
|---|---|---|---|
| 437 → 443 | 17 / v6 | 人数预期改为实际儿童、婴儿均未勾选；其他预期保留 | build 46 / run 60 失败，不计通过 |
| 438 → 444 | 18 / v4 | 同上，保留恢复操作、字段保持和停止边界 | build 47 / run 58 通过；独立复跑 59、61 均通过 |

443 的最新失败发生在前置条件准备：预期“不限舱等”，实际显示“经济/超经舱”。上一轮尝试在面板内选择“不限舱等”超时；本轮仍未可靠地建立用例要求的状态。该用例后续还需核对红色校验样式，不能删掉这些断言换取通过。

实际现场曾出现人数展示及“经济/超经舱”，其他现场显示内联勾选项和“不限舱等”。入口观察与操作后的状态可能不同，**原因尚未确定**；不能直接归因于 A/B 测试，或断言单程模式一定没有某个控件。

444 的修复解决了选择面板遮挡和准备校验状态的问题。v4 按真实页面进行清空、关闭面板、触发空城市校验，再选择上海并检查其他字段。run 59、61 分别耗时约 9.14、10.33 秒，普通复跑不调用 LLM。

人工查看 run 61 最后一步截图还发现：上海值已恢复，但原“请选择出发城市”提示仍在。冻结用例没有要求恢复后错误提示消失，因此这不是本次已通过断言的覆盖内容，也不能声称已经验证该提示正确清除。后续应另补一条明确检查提示消失的用例。部分“按钮未被遮挡”检查使用面板已关闭及按钮可见、可用等证据，尚未统一增加实际命中测试。

本轮已修正覆盖审查规则：历史失败截图用于定位旧错误，不能直接当作当前修复代码已经失败的结论；当前代码仍须保留完整预期并实际运行。恢复额度后，两个修订版均已完成这一流程，结果分别为失败和通过。最后增加的按需选择、不得猜测颜色值等提示约束已加载；上述成绩来自本次迭代中保存的具体版本，并非重载后重新从零生成全部样本的成绩。

## 已落地的通用修改

1. 增加“实测生成”：冻结用例 → 读取真实页面 → 生成 → 语法和覆盖审查 → 试跑 → 最多两轮自动修订。
2. 采集真实 DOM、ARIA、唯一定位候选、动态输入面板及失败现场；发送模型前隐藏敏感输入值。
3. 公共操作处理面板开闭、限定范围选择、自定义勾选状态和位置关系；拒绝用强制点击掩盖遮挡。
4. 区分历史状态与当前代码，保留原预期；不把正常页面误写成无条件停止，不把跳过当通过。
5. 已知动作缺少操作后依据时，可在审查通过后进行一次诊断采集；诊断强制不计通过，不能绕过语法约束。
6. 失败修复保留每个版本、报告和截图；取消任务会使迟到结果失效；执行器按任务租约串行工作。
7. 普通“运行”执行已保存代码，不调用 LLM；模型额度错误不会影响已有脚本的直接运行。
8. 明确显示 401、402、403、429 和服务端异常，避免暴露供应商响应正文或凭据。
9. 强调条件选择必须检查当前选中状态，已有选中状态不重复点击；颜色样式需来自真实页面证据，不猜固定 RGB，也不以“非黑色”等较弱断言替代。

方法参考 [Playwright Test Agents](https://playwright.dev/docs/test-agents)、[Codegen](https://playwright.dev/docs/codegen)、[Playwright MCP](https://github.com/microsoft/playwright-mcp) 和 [Stagehand Observe](https://docs.stagehand.dev/v4/basics/observe)。本平台仍采用自己的 Python 执行器和报告系统，未引用其他工具的成功率。

## 使用方式与后续

在项目中配置被测网站入口，进入**用例管理 → 生成脚本 → 实测生成**，选择在线执行器。已有脚本进入**代码与记录 → 实测生成 / 修复**。实际通过后可直接点击**运行**复跑。

当前可在脚本页面运行 431–436、444 对应的已验证版本；443 保留失败状态，可在取得后续页面状态依据后继续修复。后续优先扩大独立网站与业务样本、补充字段恢复后错误提示消失和按钮命中检查，再评估更广范围的成功率。当前结论仅为**获批修订样本 7/8 达到目标，原始样本 6/8 未达到目标**。
