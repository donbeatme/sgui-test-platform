# Playwright 实测生成

## 使用

1. 在项目管理配置唯一被测网站地址，补全用例前置条件、操作与逐步预期。
2. 在用例管理点击 **生成脚本**，选择 **实测生成** 和在线执行器。
3. 确认使用可测试的环境和数据。此模式会真实操作网站，每次使用独立浏览器，不继承个人浏览器会话。
4. 在脚本详情查看读取页面、模型生成、试跑、修订进度。失败最多自动修订两轮；任何阶段均可停止。
5. 实际运行通过的版本标记为已验证。后续 **运行** 直接执行该版本，不调用 LLM。

已有“用例直接生成”的脚本也可在详情点击 **实测生成 / 修复**。
“仅生成代码”仍可使用；此模式不打开目标网站，完成后需自行运行验证。
旧版本、每轮失败截图及执行报告都会保留。跳过、阻塞、代码草稿不算通过。

## 实现

流程为：冻结用例与入口 → 执行器读取真实 DOM/ARIA → LLM 生成 → 语法和逐步覆盖审查
→ 创建普通脚本执行记录 → 真实浏览器运行 → 成功结束或利用失败现场修订。

- `ScriptBuild` 保存生成状态、执行器、轮次、观察结果和最近执行。
- 观察与执行均使用带租约的队列；取消会使迟到的结果失效。
- 页面观察提供真实属性、可见性、祖先容器和 CSS 候选；密码等敏感输入在发送前脱敏。
- 页面加载后额外等待有界的界面稳定过程，识别动态渲染的业务表单。只探查普通输入框入口，不填值、不提交表单；记录实际展开的下拉框和日历，优先保留新出现的控件。
- 定位候选在实际 DOM 中核对唯一性，处理重复字段和深层嵌套；不能用任意 `first()` 隐藏歧义。入口 HTTP 错误会保留页面证据并停止生成。
- 同项目同入口的成功定位器可以复用；不能套用其他用例的业务预期。
- 只有真实操作和正向断言证明存在的控件才能作为历史定位依据；“不存在”“已隐藏”的断言通过，不代表该定位器指向真实控件。
- 实测模式使用本轮页面、冻结预期和历史代码，避免重复塞入整份旧页面日志；原始日志仍保留在来源记录中。
- 同一冻结用例若有当日生成且已通过的 AI 版本，会复用其代码另存新版本并重新试跑；不会继承历史通过结论。这样避免重复生成破坏有效代码，跨日默认参数则重新生成。
- 失败修订收到原代码、冻结预期、实际错误、失败时 DOM/ARIA；不得删除断言、吞异常或改期望值求通过。
- 若仅缺少操作后的状态依据，且审查确认全部动作定位明确、严格处于原用例范围内，可进行一次诊断采集。它保留实际字段、样式和截图，强制不计为通过；后续仍须补齐断言、覆盖检查和真实试跑。格式不合格、动作范围不明的草稿不会执行。
- 城市和日期选择使用限定容器的公共操作；自定义复选框先检查当前状态，再按需切换。普通运行始终执行保存的代码，失败不会偷偷调用模型更改断言。
- 试跑复用正常执行器和服务端证据判定，必须有完整步骤结果和本轮截图。模型不能自行宣称“已验证”。
- 页面、网络或权限问题仍可能阻塞；经过验证的某版本也不能保证未来网站变化后永远通过。

## 参考

- [Playwright Test Agents](https://playwright.dev/docs/test-agents)：规划、生成、运行和失败修复的闭环，生成时检查真实页面。
- [Playwright Codegen](https://playwright.dev/docs/codegen)：从真实操作构造定位器，优先语义及可唯一定位的目标。
- [Playwright MCP](https://github.com/microsoft/playwright-mcp)：利用浏览器可访问性快照为模型提供实际页面依据。
- [Stagehand Observe](https://docs.stagehand.dev/v4/basics/observe)：将观察到的目标用于后续操作。

本平台采用上述思路，保留 Python 运行器及现有报告体系。不会把其他工具的通过率当作本平台实测结果。

## 验收口径

主样本为固定的携程 431–438 共 8 条既有业务用例，原步骤、预期和修订标识在测试前冻结。
最终版本另做两次独立复跑。生成失败、草稿、阻塞和跳过都不能计入成功。
另外使用 Playwright 官方 TodoMVC 演示页验证新增、完成、筛选、编辑取消和刷新持久化。
这两组分别报告，不用简单页面的结果抬高携程样本通过率。

实际样本、原始结果和失败记录保存在部署的数据目录；统计与尚未完成事项见
[2026-10-20 实测记录](playwright-evaluation-2026-10-20.md)。当前原始携程样本为 6/8（75%）；
采用用户批准并另行保留的两条界面预期修订版后为 7/8（87.5%），通过的 7 条最终版本各独立复跑两次，共 14/14 次通过。
这是经过修复后的样本成绩，不是首次生成成功率，也不是所有网站的成功率保证；剩余失败与覆盖局限见实测记录。
