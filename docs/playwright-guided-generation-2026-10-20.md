# 生成阶段交付 Playwright 脚本

本次修改对应“点击生成脚本后，后台完成实现与验证，最终交付可用代码”的需求。默认从用例生成入口采用 `guided-v1`，未改写原始用例预期，没有手动修改本轮生成的代码。

## 实现

1. 冻结用例步骤、预期和项目入口，领取有租约的独立浏览器会话。
2. 模型读取当前 DOM/ARIA，每次提出最多六条操作或断言。打开新的面板后继续观察；当前步骤完成时也可单独提交完成标记。格式错误或连续重复切换入口时，先在原会话进行一次修正，不丢弃已成功的操作。
3. 执行器逐句执行。后端只收录执行器确认成功的语句，失败后的后续语句不执行、不进入代码。请求重复确认不会重复记入代码；参数不能在中途改值以迎合结果。
4. 要求代码主动准备目标状态，使用幂等选择、勾选等操作；每步“保持不变”的条件需重新断言。此前失败记录仅作为诊断参考，不改变原始预期。
5. 按原步骤顺序确定性组装已执行的语句。覆盖审查获得实际操作记录、途中新出现的控件证据、最终页面和已验证定位器；区分明确覆盖缺口和非阻塞提示。
6. 在两个新的独立浏览器环境中复跑。两次通过才交付为“可用”；失败在后台重新观察和修复，最多三轮。历史脚本复用同样重新跑两次，且只限同一冻结用例、同入口、当天已通过覆盖检查并运行成功的 AI 版本，不复用仅手改后运行通过但未经覆盖审查的代码。
7. 停止、旧租约回调、后台队列错误和模型服务错误不会把未完成任务标为可用。单纯完成浏览器操作采集不计为通过。

前端默认只呈现生成中、可用或失败原因。高级配置、版本、编辑和内部记录保留在可选技术详情中。原“从 LLM 执行记录保存”功能保留。

## 验证口径

- 后端模块回归 88 项通过；最终原会话修正、复用来源等 12 项专项回归通过。
- 执行器 34 项真实本地浏览器测试通过，包含保持会话、逐句失败确认、停止后续动作及 HTTP 拒绝。
- Vue 类型检查和生产构建通过。
- 新生成任务均由平台 API 正常入口创建，使用平台配置的模型和 Windows 执行器。没有向生成结果写入手工代码。
- 用例 445、446 是分别来自 441、432 的验收副本，原步骤与预期不变；原用例保留。

实测过程发现并修复了后台任务注册、空完成标记、初始条件准备以及中间观察证据未传入审查的问题。另捕获了连续点击浮层入口在慢速学习与快速复跑中表现不同的问题：生成前检查此类重复动作，要求使用幂等浮层操作。失败的脚本 22、23 与构建记录保留，不将这些开发过程的失败从记录中抹除。单次验收不能推出任意网站、任意用例均达到 80%。

## 适用边界

目前支持执行器契约内的单页面导航、表单、选择、状态与常见断言；复杂多标签页、框架之外的任意 Python、系统调用不自动运行。目标站点真实业务错误、登录/验证码、网络故障、控件变化仍可能阻塞；不能删除原预期或用宽松断言换取通过。日期参数在生成时计算，跨日运行仍需检查。
