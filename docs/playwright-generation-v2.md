# Playwright 脚本生成流程

用户从用例管理的“生成脚本”入口提交。新任务采用基础通过标准：生成脚本后，在新的独立浏览器环境中完整复跑一次，无执行错误即标记“复跑通过”，允许运行和下载。

本标准验证脚本能够重跑，不代表业务覆盖已经完备。额外的覆盖评审和多次稳定性验证后续再加入。策略随构建和版本保存，历史任务仍保留原标准与结果，不因新规则自动改成通过。

## 生成与修复

1. 冻结用例原文、步骤、预期和项目入口，直接提供给生成模型。基础模式不另调用模型规划前置与验收清单。
2. 执行器读取实际 DOM、可访问性快照及控件状态。有限快照优先保留选中状态、打开的弹层、表单值及新显示的控件，减少导航和背景列表挤占内容；截图或页面仍有截断时，不将未采集到的控件当作不存在。模型输出受限的 Playwright 操作片段；校验通过后执行，只保留执行器确认成功的语句。
3. 同一已观察页面内可批量执行最多 12 条操作或断言；打开新面板后先观察，再操作新控件。历史定位记录按构建读取，不在每个微小动作中重复查询。
4. 对“控件不存在”的停止判断检查当前可见 DOM 的文案和值。出现矛盾时要求改正；首次停止判断要求重新读取页面。未在有限快照中找到控件不等于已经证明不存在，模型仍需检查可能尚未展开的面板。
5. 失败时保留已完成步骤和未执行的代码。已完成且不在故障范围内的步骤在新上下文中直接重跑；错误步骤使用局部补丁，其他语句保持不变。仅打开控件以观察状态的补丁不会自动结束该步骤。自动修复次数仍有上限，不无限重试。
6. 最终代码仅做语法、运行接口、参数与步骤结构检查，不强制每步都包含断言，不再单独调用 AI 进行覆盖复核。原用例中可观察的预期仍指导生成；已有断言会真实执行，失败不会被忽略或删除。
7. 保存后的最终版本在一个新的独立浏览器环境中完整复跑一次。执行完成且无错误即通过；修复前的成功记录不能替代新版本的复跑。操作超时、异常、断言失败、中断及未完成步骤仍不能判为通过。
8. 截图继续作为辅助记录保存。基础模式中，截图保存失败会记录提示，但不会改变代码本身的执行结果；运行过程错误仍保留。旧任务和 LLM 执行的证据要求不变。

## 通用浮层操作

`record.dismiss_panel(panel=..., dismiss=...)` 只在指定面板打开时点击明确的关闭控件或中性区域，并验证面板实际关闭。不能把搜索、订单等业务按钮当作关闭按钮，也不使用 `force` 穿透遮挡。

## 相对日期

参数值支持运行时模板，例如：

```json
{
  "date_D": "{{date:7:iso}}",
  "day_D": "{{date:7:day}}",
  "weekday_D": "{{date:7:weekday_zh_short}}"
}
```

每次执行按执行机器的本地日期解析。固定日期仍可直接写入参数。格式包括 `iso`、`day`、`day2`、`month`、`month2`、`year`、`weekday_zh`、`weekday_zh_short`、`weekday_iso`。日期定位器和断言也应引用这些参数，不能把生成当天计算出来的年月日或星期写死在代码里。

下载的独立 Python 文件包含同一套日期解析和浮层操作实现。基础复跑模式需要 runtime version 9 或更新的执行器；旧脚本仍按其要求选择兼容执行器。

## 证据与评估

构建记录保存采用的通过标准、版本关联、原始操作确认、错误位置、局部补丁结果和操作生成耗时。基础模式不执行单独的准备计划与覆盖复核，因此不会伪造这两个阶段的完成记录。服务超时、未触发场景或未完成运行不会当成通过。

当前通过率仅表示生成脚本在指定环境中完整复跑成功的比例，不等于业务覆盖率，也不保证后续网站变化后仍可运行。若用户要求停止测试，只修改代码与部署，不自动恢复样本测试。
